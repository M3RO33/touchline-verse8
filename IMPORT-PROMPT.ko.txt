현재 Verse8의 TOUCHLINE 프로젝트를 첨부한 v16 / 1.14.0 소스로 업데이트해주세요. 새 프로젝트라면 같은 소스를 이식해주세요.
첨부한 소스는 선배 심판의 무전으로 시작하는 첫 휘슬 입문 경기, 밝은 경기 배정표와 독립 3D 쇼룸 로비, 하단 VAR 콘솔, 새 Quaternius 인체·축구복·LOD 및 출처가 있는 애니메이션 곡선, 5개 스테이지와 커리어·판정 제한시간을 구현했습니다. 새로 재구현하지 말고 경기 로직·3D·모션·UI를 유지해 연결해주세요. Verse8에서 별도로 수정한 내용이 있으면 먼저 차이를 확인해 보존하고, 충돌하는 기능은 보고해주세요.

먼저 첨부 파일을 실제로 읽을 수 있는지 확인하고 파일 목록을 보여주세요. ZIP 내용을 읽지 못했다면 추정해서 만들지 말고 텍스트 소스 및 public/assets의 바이너리 파일을 요청해주세요. 텍스트 버전의 === FILE: 경로 === 구분자 사이 내용이 각 코드 파일의 원문입니다. BINARY ASSET 표기는 원본이 아니므로 반드시 ZIP의 실제 파일을 사용합니다.

1. 현재 프로젝트 파일 구조, package.json, Vite 설정, 시작 파일과 플랫폼 설정을 먼저 확인해주세요. 기존 환경변수, Verse ID, SDK 인증·호스팅 설정은 유지합니다.
2. src/game 전체와 src/App.tsx, src/main.tsx, index.html, public/assets 전체를 연결해주세요. 모델을 구·원통 조합으로 다시 만들지 마세요. 자산 해시는 SOURCE-PROVENANCE.json과 일치해야 합니다. 기존 플랫폼 설정과 충돌하지 않게 package.json과 Vite 설정을 병합합니다. three 버전은 0.180.0을 사용합니다. locomotion-clips.mjs와 kick-reference.mjs를 포함한 전체 모듈을 보존하세요. UAL은 작가 제작 애니메이션이며 CMU 10_03은 실제 모션 캡처 참고 곡선입니다. 공과 발 접점은 게임 IK를 사용하므로 source 좌표를 그대로 덮어쓰지 마세요. 서버 연동 없이 싱글플레이를 먼저 동작시킵니다. 게임 메뉴와 licenses 폴더의 모델 출처·라이선스를 유지합니다.
3. DOM 마운트 완료 후 게임 app.js를 한 번만 초기화합니다. React StrictMode나 중복 useEffect로 RAF 루프와 DOM 이벤트가 두 번 실행되지 않게 해주세요.
4. 경기 약 5분, 8개 판정 장면, 일반 플레이, 카드 평가 제외, 오프사이드의 간접 프리킥 자동 적용, 전후반 각 0–30분 추가시간, VAR와 카메라, 봉급 평가를 모두 유지해주세요. 5개 스테이지, 레벨·평판·자금, 로비의 심판 아바타, 실제 시간 판정 제한과 시간 초과 처리, 새로운 반칙 동작도 유지합니다.
5. 첫 휘슬은 first-whistle.mjs의 입문 상태와 rulebook.mjs의 용어 설명을 유지합니다. 접촉/패스 순간 이동, 다른 각도 확인, 두 기준선 배치를 직접 수행한 뒤 판정하고, 오답은 근거를 보고 재시도합니다. 연습 도입·수료 기록은 touchline.first-whistle.v1에 별도 저장하며 기존 touchline.career.v1의 평판·자금·해금·경기 수를 초기화하거나 연습 결과로 변경하지 마세요. 기존 프로필도 로비·메뉴에서 이야기 재실행과 건너뛰기가 가능해야 합니다.
6. 방송형 점수판과 밝은 경기 배정표·5단계 레일·독립 3D 쇼룸, 넓은 상단 리플레이와 하단 판정 콘솔, 기본/상세 VAR, 접이식 징계, 용어 수첩, 결과의 근거 장면 재생, 실제 기록 기반 최종 경기 보고서 UI를 유지합니다. 외부 웹 폰트·장식성 카드·홍보 문구를 임의로 추가하지 마세요. 근거 재생에서 판정 평가와 수당 정산이 중복 실행되면 안 됩니다.
7. Preview에서 첫 휘슬 3장면을 수료하고 기존 자금·해금이 보존되는지 확인한 뒤 경기 시작, 3D 렌더링, 일시정지, 카메라 변경, 추가시간 +5분 설정, 첫 VAR의 접촉/휘슬 이동, 프레임 이동과 판정 후 경기 재개를 검증해주세요. 브라우저 콘솔 오류도 확인해주세요.
8. iframe 안의 전체 화면과 저장소 제한을 실제로 확인해주세요. 서버 저장·랭킹·결제 기능을 임의로 추가하지 마세요.
9. 빌드 및 Preview 검증 결과와 수정한 파일을 보고해주세요. 공개 Launch는 Preview 검증 후 진행합니다.
